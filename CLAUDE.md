# Stash Exists Checker - Reptyle

Tampermonkey userscript for desktop Chrome that shows, on supported sites (one adapter per site: Reptyle, Adult Time, Brazzers), what is already in your local [Stash](https://stashapp.cc) (`http://localhost:9999`): a badge on video pages and a dot on video cards (Reptyle), the matching performer with an add-URL button on model pages, and in-Stash marks on videos and models everywhere. Since v3.0.0 it also carries everything `reptyle-stash-model-link` (8.5.0) did; that script must not run next to it (both use the same element ids). Independent of the other userscripts in the docker-stuff workspace; it is set up like `colum-manager` (one dependency-free userscript, no build step).

@AGENTS.md

## Project map

- `stash-exists-checker.user.js` is the installable userscript. Most of it is the model-link code in the original ES5 `var` style; the video badge and card dots (`postGql`, `lookupVideo`, `checkDetail`, `pumpCards`, `checkCards`) keep the checker's ES2020 style.
- `SITES` (site adapters: paths, selectors, `sceneUrlParts`, optional `nameFromUrl`, `anchorSel` (empty = floating panel), `sceneKey`/`modelKey`/`modelUrl`, and the optional `scenePage`/`sceneTitleSel`/`cardDots` for the video badge and card dots, set only on Reptyle) sits above the `module.exports` guard; the core picks the adapter with `siteFor(location.hostname)` and reads every page-specific value from it. `SITES`, `siteFor`, `cachedList`, `lookupVideo`, `norm`/`canonUrl`, the shared log sink (`logPage`, `createLogSink`; `docker-workspace/docs/userscripts.md`) and the pure helpers (`normUrl`, `normTitle`, `normName`, `extractMovieId`, `extractModelId`, `extractGammaSceneId`, `extractGammaActorId`, `gammaNameFromUrl`, `ayloId`, `ayloNameFromUrl`, `modelIdFromParam`, `modelNameFromParam`) are exported for tests; everything else needs the page. `STASH_ORIGIN`/`ENDPOINT` and the `lookupVideo` constants sit above the guard so the exported functions see them.
- Each adapter host needs a whole-site `@match`; `test/core.test.cjs` fails if `@match` and the adapter hosts differ. Stash usually stores public tour URLs while members areas use other hosts, so scenes are matched by `sceneKey`, not by full URL. Adult Time (Gamma) shares scene ids across all Gamma sites, so its adapter reads every `/en/video/` URL in Stash. Video cards are the outermost `videoCardSel` matches that link exactly one scene (`videoCards`); an empty `videoCardSel`/`modelCardSel` switches to `structuralCard` (Brazzers). `modelParam`/`modelNameParam` make filtered pages (`?models=<id>`, Adult Time "See all") model pages; `performerUrlParts(id)` finds the performer by id first; model pages are remembered with `GM_setValue` (`model:<site>:<id>` and `model:<site>:name:<name>`).
- Card dots are queued and checked in batches of four with a 150 ms pause (`pumpCards`). A card whose scene id is in the stored scene list is answered from it; the others go through `lookupVideo` (exact title and canonical URL), cached per title + URL. The dot sits top right so it never covers the `IN STASH` card badge (top left); the dot reads the title without the model-page `✓ ` prefix.
- `markModelCards` carries a documented `eslint-disable-next-line no-loop-func`: its handlers read the shared performer cache at click time on purpose.
- `test/core.test.cjs` holds the unit tests (Node's built-in runner). `test/browser.cjs` drives headless Chrome over stub pages of every adapter (CDP, request interception, stubbed GM APIs and Stash); add a scenario there for each new adapter. `tools/` holds the two lint entry points copied from `colum-manager` and `check-version-bump.cjs`; all read `<package name>.user.js`.

## Validation

- `npm run check` = `lint` + `test` + `test:browser` + `version-bump` (fails if the userscript differs from `origin/master` without a higher `@version`; installs auto-update from there). `lint` runs the Tampermonkey 5.5.1 ESLint worker from the Windows Chrome profile and fails if that extension version is not installed; it also asserts `@version` equals the runtime `VERSION`. `test:browser` needs desktop Chrome (`CHROME_PATH` overrides the path).
- `npm run check:ci` = `lint:ci` + `test` + `version-bump` (needs `npm ci --prefix tools/lint-ci` once). `.github/workflows/ci.yml` runs it.
- Single test file: `node --test test/core.test.cjs`.
- Releasing: bump `@version`, `VERSION` and `package.json` together (currently 3.0.0), then follow AGENTS.md. Installed copies auto-update from the raw file on `master` (`@updateURL`/`@downloadURL`, asserted by a test), so every push that changes the script must raise `@version`, and a broken push reaches every install. Keep `@name`/`@namespace` unchanged so Tampermonkey updates the installed script instead of adding a second one.

## Architecture

- One IIFE; sites like Reptyle are single-page apps, so the script matches whole sites and acts on the current path. Keep page changes idempotent and never rely on a load event per page. Two loops follow navigation: a 2-second re-check (panel, video and model marks) and a mutation observer plus `pushState`/`popstate` (video badge, card dots).
- The floating panel (adapters without `anchorSel`) lives in the shared bottom-right `#userscript-dock` (`dockPanel`, order 35) and lookups/failures go to the local log collector (`script` = `stash-exists-checker`); see `docker-workspace/docs/userscripts.md`.
- Grants: `GM_xmlhttpRequest` (Stash and the log collector), `GM_getValue`/`GM_setValue` (remembered model pages, panel fold state, shared Stash lists) and `GM_addStyle` (video badge and dot styles).
- The two bulk Stash lists (all performers; scenes per `sceneUrlParts` entry) go through `cachedList` (exported, unit-tested): raw rows in GM storage under `cache:v1:*`, shared by every site and tab, used at once, refetched after 10 minutes, ignored after a day; each site builds its own maps from them (`buildPerformerMaps`, `buildSceneMap`). `addPerformerUrl` drops `cache:v1:performers`. Per-model lookups and `lookupVideo` stay live. Bump the `v1` prefix if the stored row shape changes. In `test/browser.cjs` GM storage is one Node-side store for all hosts (CDP binding); wait with `stored(...)` for a write to land before navigating. Network access is only through `GM_xmlhttpRequest` and the matching `@connect` entries; `siderRuntime` (the runtime the code was originally written for) must not come back.
- The only Stash write is `performerUpdate` in `addPerformerUrl`, which always asks `confirm()` first, then reads the performer's live `urls` (`findPerformer`) and appends to them, because the update replaces the list and the performer object may come from a stored list.
- Never store session tokens, `?r=` parameters, cookies, HAR data, signed URLs or account names in this repository.
- Running it for real needs Tampermonkey in desktop Chrome, a logged-in session on the site and a running local Stash; none of that is available to the tests.
