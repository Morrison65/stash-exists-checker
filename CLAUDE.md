# Stash Exists Checker - Reptyle

Tampermonkey userscript for desktop Chrome that shows what is already in your local [Stash](https://stashapp.cc) (`http://localhost:9999`): a badge on video pages, a tag on every video card (found by URL, title or file name), the matching performer with an add-URL button on model pages, and in-Stash marks on videos and models. Built-in adapters: Reptyle, Gamma members sites (`gammaSite`: Adult Time, DFXtra), Aylo (`site-ma.<brand>.com`: Brazzers and the rest of the network). Since v4.0.0 it runs on every page (`@match *://*/*`) and any other site can be onboarded with the setup guide in the Tampermonkey menu, whose picks become a stored site profile. Since v3.0.0 it also carries everything `reptyle-stash-model-link` (8.5.0) did; that script must not run next to it (both use the same element ids). Independent of the other userscripts in the docker-stuff workspace; it is set up like `colum-manager` (one dependency-free userscript, no build step).

@AGENTS.md

## Project map

- `stash-exists-checker.user.js` is the installable userscript. Most of it is the model-link code in the original ES5 `var` style; the video badge and card tags (`postGql`, `lookupVideo`, `checkDetail`, `pumpCards`, `checkCards`, `showTag`) keep the checker's ES2020 style.
- **Order matters.** On a site that is neither built in nor set up, the script registers the menu entry and returns right after the module guard. Everything the setup guide needs on such sites is a function declaration (hoisted) or a `var` above the guard (`SETUP_ID`, `picking`, `PROFILES_KEY`); a `var` assigned below the early `return` is `undefined` there.
- **Site profiles** (setup guide output, JSON only, GM key `profiles:v1` by exact host). Each pick kind (`PICK_KINDS`: model, listing, card, video, performerLink) holds one example (object, as saved by 4.0/4.1) or several (array; `examples()` normalizes); `profileSite` joins paths (`joinPaths`) and selectors (`joinSel`) and keeps one key rule per link prefix (`keyRules`, `profileKeys`). A card example may carry `cardSel` (its own class); only when every card example has one does it become `videoCardSel`. `linkPrefixOf`/`pathPatternOf`/`keyModeOf` derive rules from picked pages, `profileKey` keys site links and Stash tour URLs alike (last numeric path segment; in slug mode the segment right after the prefix on the own host, else the last segment; own-host links must start with the prefix or a tour form of it, `tourPrefixes`: `/members/video/` also matches `/video/`, which is what Stash holds for members areas), a listing example picked on a video page or a page of videos (`videoPageOf`, `listingPageOf`) counts as a `performerLink` both in `profileSite` (4.1.0 profiles hold such picks) and in `derivePick`, `validProfile` rejects broken ones, `profileSite` turns one into an adapter (`strictName`: never the page title as a name; missing parts never match), and `siteFor(host, profiles)` puts a profile on top of a built-in adapter (selectors and `cardTags` only, never key functions) or makes an unknown host a site. All exported and unit-tested; the acceptance test is that sample URLs of the built-in sites give their hand-written prefixes and patterns. The picker (`startPick`) makes every element hit-testable while picking (`body * { pointer-events: auto !important }`), offers the deepest element with own text from `document.elementsFromPoint`, and lets the arrow keys adjust it; `stableClasses` takes the rarest non-generated classes. `derivePick` turns a "model list" pick inside a video card into a `performerLink` example. The guide itself (`openSetup`, `renderSetup`, `startPick`, `derivePick`, `surveyStash`) keeps its open state and draft in `setup:v1:<host>`, so it survives navigation, and logs every pick (`site onboarding`) with `describeElement` context (query strings cut from every URL).
- `SITES` (site adapters: paths, selectors, `sceneUrlParts`, optional `nameFromUrl`, `anchorSel` (empty = floating panel), `sceneKey`/`modelKey`/`modelUrl`, and the optional `scenePage` with `sceneTitleSel` (badge after the title; Reptyle) or `sceneTitleFromUrl` (title from the URL, badge floating in the dock at order 34; Adult Time, Aylo), and `cardTags` (all three)). `sceneUrlParts` entries are fragments (`url INCLUDES`) or `{ name, regex }` (`url MATCHES_REGEX`, Go regex syntax, one stored list `cache:v1:scenes:<name>`): the Aylo adapter uses one regex over `AYLO_DOMAINS` (the brands of the installed AyloAPI community scrapers), because Aylo keeps one scene id across the network and Stash often holds a Brazzers scene under a BangBros URL sits above the `module.exports` guard; the core picks the adapter with `siteFor(location.hostname)` and reads every page-specific value from it. `SITES`, `siteFor`, `cachedList`, `lookupVideo`, `norm`/`canonUrl`, the profile helpers above, the shared log sink (`logPage`, `createLogSink`; `docker-workspace/docs/userscripts.md`) and the pure helpers (`normUrl`, `normTitle`, `normName`, `extractMovieId`, `extractModelId`, `extractGammaSceneId`, `extractGammaActorId`, `gammaNameFromUrl`, `ayloId`, `ayloNameFromUrl`, `modelIdFromParam`, `modelNameFromParam`) are exported for tests; everything else needs the page. `STASH_ORIGIN`/`ENDPOINT` and the `lookupVideo` constants sit above the guard so the exported functions see them.
- `@match *://*/*` covers every adapter host and every profile (asserted by a test); on other sites the script stays inert. Adapter ids name stored keys (`model:<id>:...`) and the `started` log entry; the Aylo adapter was `brazzers` before 4.1.0. Stash usually stores public tour URLs while members areas use other hosts, so scenes are matched by `sceneKey`, not by full URL. Adult Time (Gamma) shares scene ids across all Gamma sites, so its adapter reads every `/en/video/` URL in Stash. Video cards are the outermost `videoCardSel` matches that link exactly one scene (`videoCards`); an empty `videoCardSel`/`modelCardSel` switches to `structuralCard` (Brazzers). `modelParam`/`modelNameParam` make filtered pages (`?models=<id>`, Adult Time "See all") model pages; `performerUrlParts(id)` finds the performer by id first; model pages are remembered with `GM_setValue` (`model:<site>:<id>` and `model:<site>:name:<name>`).
- Card tags are queued and checked in batches of four with a 150 ms pause (`pumpCards`). A card whose scene id is in the stored scene list is answered from it; the others go through `lookupVideo` (exact title, then file name via a quoted path `INCLUDES`, which Stash runs as one `LIKE '%w1%w2%...'`, verified on the returned basenames; the URL query only while the list is missing; no fuzzy count), cached per title + URL. `cardFor` finds the card like `videoCards` does; the tag goes in its top-left corner, never into the title, and not where the `IN STASH` badge of `markVideos` already is (that badge removes a tag it supersedes). `card.dataset.stashQueued` holds the key, so a card the site reuses for another video is rechecked; a "card" that links more than one scene (sibling previous/next links share their parent as structural card) is skipped, because it flipped between both keys on every pass and each flip triggered the next (4.1.0 Brazzers video pages, browser test `nav.sib`). Titles are read without the model-page `✓ ` prefix.
- `markModelCards` carries a documented `eslint-disable-next-line no-loop-func`: its handlers read the shared performer cache at click time on purpose. It runs on listing pages only, never badges a card that links a video (a structural "model card" around a performer link in a video card is a video card), and marks badged cards with `data-sml-model-card`; `markModelLinks` runs on every page and skips links inside such cards. The performer badge reads `✓ PERFORMER IN STASH` (purple) so it never reads as a video mark.
- `test/core.test.cjs` holds the unit tests (Node's built-in runner). `test/browser.cjs` drives headless Chrome over stub pages of every adapter (CDP, request interception, stubbed GM APIs and Stash); add a scenario there for each new adapter. `tools/` holds the two lint entry points copied from `colum-manager` and `check-version-bump.cjs`; all read `<package name>.user.js`.

## Validation

- `npm run check` = `lint` + `test` + `test:browser` + `version-bump` (fails if the userscript differs from `origin/master` without a higher `@version`; installs auto-update from there). `lint` runs the Tampermonkey 5.5.1 ESLint worker from the Windows Chrome profile and fails if that extension version is not installed; it also asserts `@version` equals the runtime `VERSION`. `test:browser` needs desktop Chrome (`CHROME_PATH` overrides the path).
- `npm run check:ci` = `lint:ci` + `test` + `version-bump` (needs `npm ci --prefix tools/lint-ci` once). `.github/workflows/ci.yml` runs it.
- Single test file: `node --test test/core.test.cjs`.
- Releasing: bump `@version`, `VERSION` and `package.json` together (currently 4.3.0), then follow AGENTS.md. Installed copies auto-update from the raw file on `master` (`@updateURL`/`@downloadURL`, asserted by a test), so every push that changes the script must raise `@version`, and a broken push reaches every install. Keep `@name`/`@namespace` unchanged so Tampermonkey updates the installed script instead of adding a second one.

## Architecture

- One IIFE; sites like Reptyle are single-page apps, so the script matches whole sites and acts on the current path. Keep page changes idempotent and never rely on a load event per page. One scheduler (`tick`) follows the page: a mutation observer (child lists, text, `href`) marks it dirty and runs a pass at most once a second, `pushState`/`replaceState`/`popstate` run one at once, list arrivals mark it dirty, and a 2-second heartbeat refreshes the lists. A clean pass returns at once; a pass computes the video cards once, memoizes `keyCount` (`passMemo`) and drops its own mutations with `takeRecords()`. Only the newest performer lookup may draw the panel (`detailLookups`).
- The floating panel (adapters without `anchorSel`) and the setup guide live in the shared bottom-right `#userscript-dock` (`dockPanel`, orders 35 and 36; the floating video badge 34) and lookups/failures go to the local log collector (`script` = `stash-exists-checker`); see `docker-workspace/docs/userscripts.md`.
- Grants: `GM_xmlhttpRequest` (Stash and the log collector), `GM_getValue`/`GM_setValue` (site profiles, setup drafts, remembered model pages, panel fold state, shared Stash lists), `GM_addStyle` (video badge and tag styles), `GM_registerMenuCommand` (setup entry) and `GM_setClipboard` (profile export).
- The two bulk Stash lists (all performers; scenes per `sceneUrlParts` entry) go through `cachedList` (exported, unit-tested): raw rows in GM storage under `cache:v1:*`, shared by every site and tab, used at once, refetched after 10 minutes, ignored after a day; each site builds its own maps from them (`buildPerformerMaps`, `buildSceneMap`). `addPerformerUrl` drops `cache:v1:performers`. Per-model lookups and `lookupVideo` stay live. Bump the `v1` prefix if the stored row shape changes. In `test/browser.cjs` GM storage is one Node-side store for all hosts (CDP binding); wait with `stored(...)` for a write to land before navigating. Network access is only through `GM_xmlhttpRequest` and the matching `@connect` entries; `siderRuntime` (the runtime the code was originally written for) must not come back.
- The only Stash write is `performerUpdate` in `addPerformerUrl`, which always asks `confirm()` first, then reads the performer's live `urls` (`findPerformer`) and appends to them, because the update replaces the list and the performer object may come from a stored list.
- Never store session tokens, `?r=` parameters, cookies, HAR data, signed URLs or account names in this repository.
- Running it for real needs Tampermonkey in desktop Chrome, a logged-in session on the site and a running local Stash; none of that is available to the tests.
