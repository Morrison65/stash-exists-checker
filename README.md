# stash-exists-checker

Tampermonkey userscript for **desktop Chrome** that shows what is already in your local [Stash](https://stashapp.cc) (`http://localhost:9999`). Version **4.1.0**. Built in: Reptyle (`app.reptyle.com`), Adult Time members (`members.adulttime.com`) and the Aylo members areas (`site-ma.brazzers.com`, and `site-ma.<brand>.com` for BangBros, Reality Kings, Digital Playground, Babes, FakeHub and the other Aylo brands). Any other site can be onboarded from the Tampermonkey menu (see [Onboarding a new site](#onboarding-a-new-site)).

**v4.1.0** fixes Brazzers scenes Stash holds under another Aylo brand's URL, and adds the video page badge to Brazzers and Adult Time:
- **Aylo network.** Aylo keeps one scene id across all its sites, and the scrapers often save a Brazzers scene under its BangBros (or Reality Kings, ...) tour URL. The Brazzers adapter only read brazzers.com URLs, so such scenes were not marked on cards or found on their page. It is now one adapter for the whole Aylo network: scene and model ids count on every Aylo domain handled by the installed AyloAPI scrapers, and the scene list is one regex query over all of them (in this library 498 scenes instead of 206). The other Aylo members areas (`site-ma.<brand>.com`) use the same adapter; only Brazzers was seen live.
- **Video page badge on Brazzers and Adult Time.** Their video page title element is not known, so the badge takes the scene id and title from the URL (`/scene/<id>/<slug>`, `/en/video/<channel>/<Title>/<id>`) and floats in the bottom-right dock. Picking the title with the setup guide moves it next to the title.

**v4.0.0** runs on every page and adds the setup guide:
- **Every site.** `@match *://*/*`. On a site that is neither built in nor set up, the script does nothing but add **Stash: set up this site** to the Tampermonkey menu: no Stash request, no log entry, nothing drawn. Tampermonkey asks you to confirm the wider match and the new grants (`GM_registerMenuCommand`, `GM_setClipboard`) once in its dashboard; until you do, 3.0.0 keeps running.
- **Setup guide.** On the site's own pages you click the performer name, a video title in a list, the title on a video page and, optionally, a model name in a model list. The script derives selectors and URL rules from those picks, asks Stash what it holds for the site, logs every pick with its page context to the local log collector (so built-in support can be written from the log), and **Save and turn on** makes every check work on that site at once. On a built-in site the guide changes selectors only (for example to add the Adult Time video page badge).
- **Card tags instead of dots.** The `#id`/`x` dot sat inside the title on some pages (the Reptyle front-page slider). Every card now gets one tag in its top-left corner, like the green `IN STASH` badge, and the tag says how the video was found: `✓ IN STASH` (URL/scene id), `✓ IN STASH · TITLE`, `✓ IN STASH · FILE`, or grey `NOT IN STASH`. Where the `IN STASH` badge already is, no second tag is added; a card the site reuses for another video gets a new tag.
- **File-name match.** A video Stash holds under neither its URL nor its exact title is found when a file name contains the whole title (words in order, punctuation ignored, for example `Two Cougars, One Cub - Krystal and Lexi (Part 1).mp4`). Titles shorter than three words / ten letters are not looked up that way.
- **Adult Time and Brazzers card tags.** Video cards there were only marked when Stash had the scene's URL; now every card gets a tag, checked by title and file name too.
- **Faster.** One scheduler replaces the 2-second loop and the separate mutation observer: a pass runs only when the page changed (at most once a second) or after navigation, structural card detection is memoized per pass, video cards are collected once per pass, the video page badge answers from the stored scene list without a request when it can, and card lookups skip the URL query once the scene list is loaded (two requests per unknown card instead of three).

**v3.0.0** merges [`reptyle-stash-model-link`](https://github.com/Morrison65/reptyle-stash-model-link) 8.5.0 into this script, so one script now does both jobs: the video badge and card dots of the checker, and the model-link's performer panel, add-URL buttons, in-Stash marks and the Adult Time and Brazzers adapters (its history is below). Changes against the two separate scripts:

- The card dot moved from the top left to the top right of a card, so it no longer covers the green `IN STASH` badge.
- A card whose scene id is already in the stored Stash scene list gets its dot from that list; only the other cards are looked up one by one (before, every card cost two or three Stash requests).
- The floating panel (Adult Time, Brazzers) sits at dock order 35 instead of 30, and its log entries now come from `stash-exists-checker`.
- New grants `GM_getValue`/`GM_setValue` (Tampermonkey asks to confirm them once) and `@updateURL`/`@downloadURL`: from now on the script updates itself from `master`.
- The video badge and the card dots still run on Reptyle only; the Adult Time and Brazzers video pages were not available to find their title element.

**v2.1.0** sends structured logs (start, every movie-page result, per-batch card counts, an unreachable Stash) to the local userscript log collector on `http://localhost:7790` (see `docker-workspace/docs/userscripts.md`). When the collector is not running, up to 500 entries wait in the tab's memory and are retried with backoff, and the badges work as before.

**v2.0.0** is the first release in its own repository. The code was supplied as a Sider code-agent preview (`siderRuntime`), not as a Tampermonkey script, and was ported: `siderRuntime.fetch`/`addStyle` were replaced by `GM_xmlhttpRequest`/`GM_addStyle` with explicit `@connect`/`@grant`; the Sider-only `@bound-url` and `@changelog` headers were dropped. Two latent bugs were fixed: the whitespace normaliser used `/\\s+/` (a literal backslash) so runs of spaces never collapsed, and an unreachable Stash was reported as "Not in Stash" (and cached) instead of "Stash unreachable". Original v2 behavior: lookup by canonical URL plus exact title, badge shows which matched.

## Install

1. In Chrome/Edge, turn on **Allow User Scripts** for Tampermonkey (extension details → right-click the icon → Manage extension), otherwise no userscript runs.
2. Open the [raw userscript on `master`](https://raw.githubusercontent.com/Morrison65/stash-exists-checker/master/stash-exists-checker.user.js); Tampermonkey shows its install page, click **Install** (or **Update** over an earlier version). A copy imported from a file before v3.0.0 has no update URL; install it once from this link.
3. Disable or remove **Reptyle Stash Model Link** in Tampermonkey (its features are part of this script now).
4. Reload the tab of the site. When Tampermonkey asks about cross-origin requests, review the `@connect` entries below and choose **Always allow**.

Runs on every page (top frame only). It works on the built-in sites (`app.reptyle.com`, `members.adulttime.com`, `site-ma.brazzers.com`) and on every site you set up; everywhere else it only adds the setup entry to the Tampermonkey menu.

## Updates

The script carries `@updateURL`/`@downloadURL` pointing at the raw file on `master`. Tampermonkey checks that URL on its update interval (default daily; **Utilities → Check for userscript updates** or the script's *Last updated* column forces it) and installs a pushed version when its `@version` is higher. A push without a version bump is not picked up, so `npm run check` and CI refuse a changed userscript whose `@version` is not higher than on `origin/master` (`tools/check-version-bump.cjs`).

## What it does

- **Video page** (Reptyle `/movies/<id>`, Aylo `/scene/<id>/<slug>`, Adult Time `/en/video/<channel>/<Title>/<id>`, and the video page of any site where you picked its title): a badge after the title, or floating in the bottom-right dock where the title element is not known (the title then comes from the URL). Green `In Stash #<id> (url|title|url+title|file)` links to the scene; grey `Not in Stash` (with a fuzzy-hit count) otherwise; orange `Stash unreachable` when Stash does not answer. A page whose scene id is in the stored scene list answers without a request; otherwise scenes are looked up by canonical URL (query string and `#fragment` removed, Stash `url INCLUDES`), by exact title (`title EQUALS`, whitespace and case normalised) and then by file name (a file whose name holds the whole title). If none matches, a free-text search only supplies the "similar" count.
- **Card tags** (Reptyle, Adult Time, Aylo, and set-up sites with tags switched on): one tag in the top-left corner of every video card with a title: `✓ IN STASH` (by URL/scene id, from the stored scene list without a request), `✓ IN STASH · TITLE` (exact title), `✓ IN STASH · FILE` (file name holds the title) or grey `NOT IN STASH`. Found tags link to the scene in Stash. Cards are checked four at a time; a card Stash does not hold by URL costs a title query and, for titles of three or more words, a file-name query (Stash runs it as a `LIKE` over all file paths). Nothing is shown when Stash does not answer. Where the green `IN STASH` badge of a model page is, no second tag is added. The tag sits on the whole card, never inside the title.
- **Model page** (Reptyle `/models/<id>`, Adult Time `/en/pornstar/view/<Name>/<id>`, Brazzers `/model/<id>/<slug>`, and pages filtered to one model): a panel under the name (floating in the bottom-right dock on Adult Time and Brazzers). If a performer with exactly that name (or alias, or on Brazzers the model id in a saved URL) exists in Stash, the name turns green with a checkbox and the panel shows **View in Stash**; if the page URL is not saved on the performer, **Add this URL in Stash** appends it after a confirmation (a `performerUpdate` mutation, the only write the script makes). Otherwise it lists the closest fuzzy matches. A **Retry** button appears when Stash is unreachable. The floating panel is at most 340px wide, scrolls on its own, folds saved URLs into a "Saved URLs (n)" list, and has a toggle that folds it to its summary lines (remembered).
- **Videos on a model page**: titles already in Stash (matched by the site's scene id in a stored URL, or by normalised title among the performer's scenes) get a green `✓ IN STASH` badge at the top left and a green title with a check, and the panel counts them.
- **Model listing** (Reptyle and Brazzers `/models`, Adult Time `/en/pornstars`): every model that exists in Stash gets an `IN STASH` badge, and a `+ URL` button (with confirmation) when its page URL is not saved yet.
- **Every other page** of a supported site: video cards and model links already in Stash are marked too (by id only).
- Follows in-app navigation and late-rendering cards with one scheduler: a pass runs after DOM changes (at most once a second), after `pushState`/`replaceState`/`popstate` at once, and when a Stash list arrives; a 2-second heartbeat refreshes the stored lists. An unchanged page costs nothing.

## Onboarding a new site

1. Open any page of the site, open the Tampermonkey menu (extension icon) and choose **Stash: set up this site** (on a supported site: **Stash: edit the setup of this site**). The guide opens in the bottom-right corner and stays open on every page of that site until you save or close it; the draft is kept across pages.
2. Pick, each on the right kind of page (press **Pick**, then click the element; it lights up under the mouse, the click does not reach the site, **Esc** cancels):
   - **Performer name** on a performer/model page: the name selector and which page paths are performer pages.
   - **Video title in a list** on any page with video cards: which links are videos, how their id is read (a number in the path, else the last path segment) and where the title sits in a card.
   - **Video page title** on one video page: the video page path and its title (for the badge after the title).
   - **Model name in a model list** (optional): the listing page and where the name sits in a model card.
3. **Stash URLs of this site contain** defaults to the site's domain (`members.example.com` → `example.com`); change it when Stash holds the scenes under another domain (comma-separated fragments such as `example.com/video/`). **Check Stash** shows how many scenes and performers Stash holds per fragment and the key read from sample scene URLs; it must look like the keys the guide found on the page.
4. Tick **In-Stash tag on every video card** if you want card tags there.
5. **Save and turn on** stores the profile (Tampermonkey storage `profiles:v1`) and reloads: performer panel with add-URL button, video marks, card tags and the video page badge then work like on a built-in site. **Send to log + copy** puts the profile and the Stash check on the clipboard and into the log (event `site profile exported`); **Import** takes such a JSON back; **Delete** removes the profile.

Every pick is also logged (event `site onboarding`, with the element, its ancestors, a markup excerpt with all query strings removed, the derived rules and the links found on the page), so a built-in adapter can be written from the log. Limits: a profile belongs to one exact host (`www.example.com` and `example.com` are separate); a picked model list is that exact page path (further pages of a paginated list do not count); sites whose links carry neither a number nor a stable slug per video cannot be keyed.

## Adding a site

Quickest: use the setup guide below and send the result to the log; the logged picks hold everything needed for a built-in adapter. A built-in adapter is an object in `SITES`. The fields are commented at the top of the script: page path patterns for model detail and listing pages, CSS selectors for the name, video cards and model cards, URL fragments that select that site's scenes in Stash (`sceneUrlParts`, a host or a path such as `/en/video/`), an `anchorSel` for the panel (empty for a floating panel), an optional `nameFromUrl`, and `sceneKey`/`modelKey`, which reduce a URL to the id or slug that the site's links and the URLs in Stash have in common. Members areas often use other hosts than the public URLs the Stash scrapers save, which is why the key, not the full URL, is compared. The URL patterns in the Stash community scrapers (`stash/config`, `scrapers/community/`) show which hosts and paths each network uses. Set `scenePage`/`sceneTitleSel` and `cardTags` only once the site's video page and card titles are known.

## Permissions

- `@connect localhost`: GraphQL calls to `http://localhost:9999/graphql` and log batches to the collector on `http://localhost:7790/v1/logs`. Tampermonkey asks once; choose **Always allow**. If your Stash runs elsewhere, change `STASH_ORIGIN` and add a matching `@connect`.
- `@match *://*/*` so the setup entry exists on every site. On sites that are neither built in nor set up nothing else runs: no request, no log entry, no observer.
- `@grant GM_xmlhttpRequest` for Stash and the log collector (so the sites' CSP/CORS and mixed-content rules do not apply), `GM_addStyle` for the badge and tag styles, `GM_registerMenuCommand` for the setup entry, `GM_setClipboard` for **Send to log + copy**, `GM_getValue`/`GM_setValue` for the site profiles (`profiles:v1`) and the open guide with its draft (`setup:v1:<host>`), remembered model pages (name and URL per site id), the panel fold state, and the shared Stash lists (`cache:v1:performers`, `cache:v1:scenes:<url part>`: ids, names, aliases, titles and URLs from your Stash, kept only in Tampermonkey's local extension storage). To clear the lists, delete those keys in the script's **Storage** tab in Tampermonkey (shown in the advanced config mode); they are refetched on the next page. Storage is per script, so lists and remembered model pages from Reptyle Stash Model Link are not carried over; they are fetched again on the first page.

## Checks

```bash
npm run check      # lint (Tampermonkey 5.5.1 rule set) + unit tests + browser test + version bump check
```

`npm run lint` needs desktop Chrome with Tampermonkey 5.5.1 installed (set `TAMPERMONKEY_EXTENSION_DIR` to override); `npm run check:ci` uses the pinned stand-in after `npm ci --prefix tools/lint-ci`. Unit tests cover metadata/grant consistency, the update URL, the every-site match, adapter completeness and host selection, the pure helpers, the shared Stash lists, the setup guide's rules (link prefixes and path patterns derived from sample URLs of the three built-in sites must equal what their adapters use; keys of site links and Stash tour URLs; profile validation; a profile turning an unknown host into a full site; a profile on a built-in host changing selectors only), the Aylo network rules (ids and the regex list across brands, look-alike hosts excluded), titles from video page URLs, `lookupVideo` against a stubbed `GM_xmlhttpRequest` (URL+title match, file-name match, fuzzy fallback, unreachable Stash, HTTP errors) and the shared log sink. `npm run test:browser` (part of `npm run check`, not of CI) runs every adapter in headless Chrome on stub pages with stubbed Tampermonkey APIs and Stash: panel, matches by id and title, confirm before writes, filtered model pages, late-rendering cards, re-checks, the shared Stash lists, the docked panel, the Reptyle video badge (from the list, in-app navigation, unreachable Stash), card tags on all three sites (URL, title, file name, not in Stash; one per card; following a reused card), the Aylo network list (a Brazzers members scene found under its BangBros URL) and the floating video badge on Brazzers and Adult Time video pages, and a fictional fourth site: inert before setup, the whole guide (picks captured before the page sees them, logged context, the guide surviving navigation, Stash check, export, Esc, save) and the site working afterwards. It needs desktop Chrome (`CHROME_PATH` overrides the path). Stub pages are not the live sites: real selectors are only confirmed where a page capture or report was available.
